# Image Normalize Module Spec v1.2

> 编号说明:本文档内部使用 `D-IMG-xx` 局部编号。归档进主 spec 体系时需按全局 D-series 计数器重新编号,本文档内的交叉引用需同步更新。

---

## 1. 模块定位与边界

### 1.1 职责

从商品页图片 URL 提取图片,归一化为下游 matching 模块可直接消费的标准产物。本模块是 scraping 层与 matching 层之间的独立预处理层。

### 1.2 边界(明确不做的事)

| 不属于本模块 | 归属 |
|---|---|
| 决定抓哪些图片 URL | scraping / parser 层 |
| 图片语义比对、特征提取 | matching 层 |
| 图片持久化存储策略 | storage 层(S3) |
| 反爬对抗 | 见 D-IMG-09 |

**设计依据**:与 `link_search` / scraping 模块一致的 separation of concerns 原则。matching 模块只消费"已 normalize"的产物,不感知任何压缩、格式转换、重试细节。压缩参数调整不应导致 matching 模块变更。

### 1.3 输入输出契约

- **输入**:图片 URL(单条或批量)。不假设 URL 含扩展名,不假设扩展名可信(见 D-IMG-06)。
- **输出**:归一化后的图片字节 + 结构化元数据(见 §4)。单条失败不影响批次其余条目(见 D-IMG-08)。

## 2. 决策记录

### D-IMG-01:输出格式默认 JPEG,格式本身作为可配置参数

**决策**:默认输出 JPEG。输出格式作为模块配置项而非硬编码常量。

**依据**:

1. vision 模型接收的是 decode 后的 RGB 像素矩阵,不是文件。"哪个格式画质高"是伪命题,真正的问题是**在固定字节预算下能保住多少有效信息(像素数 × 单像素保真度)**。
2. 按此标准排序:有损 WebP > JPEG > PNG。PNG 的"无损"保的是编码环节,但为塞进预算而被迫牺牲的分辨率才是真正不可逆的损失,因此 PNG 在固定预算下反而信息量最低。
3. 已确认下游 Qwen3-VL-Flash 接受 WebP,原兼容性推翻条件已满足。但文件字节是次级约束,切换 WebP 不降低 visual token 成本,因此 v1 仍默认 JPEG。
4. 保留为配置项:若后续带宽或存储成为实际瓶颈,可切换 WebP,无需改动模块逻辑。

**复核本决策的条件**:带宽或存储开销成为实际瓶颈。

---

### D-IMG-02:关闭 chroma subsampling,使用 4:4:4

**决策**:JPEG 编码时显式关闭色度抽样。

**依据**:JPEG 默认 4:2:0 将色度通道分辨率减半。对普通照片不可察觉,但对**彩色文字、logo 边缘、规格标签**会产生色彩渗漏与边缘发虚。这三类元素是 matching 环节区分会员装 / 标准装 / 不同容量规格的关键判据,已确认为高优先级保护目标。

**代价**:同 quality 下文件体积增加约 10–15%。该代价已通过 D-IMG-03 放宽字节预算吸收。

---

### D-IMG-03:长边 2048px 为主约束,文件大小 300KB 为次级约束

**决策**:分辨率上限 = 长边 2048px(主);文件预算 = 300KB(次)。

**依据**:

1. **主次关系**:vision 模型的 token 消耗由像素尺寸决定,与文件字节数无关。文件大小仅是带宽与存储的代理指标,不构成 token 成本。因此分辨率必须是主约束,字节预算是兜底。
2. **为何放宽至 300KB**:2048×2048 ≈ 420 万像素,150KB 预算折合约 0.29 bit/像素,而可接受画质的 JPEG 通常需 1–2 bit/像素,叠加 4:4:4 后需求更高。150KB + 2048 + 4:4:4 三者在最坏情况下不可同时满足,强行满足会将 quality 压至产生块效应与边缘振铃的档位——**其劣化恰好落在文字与 logo 边缘上**。
3. **失败模式分布加剧了该风险**:白底简洁构图的商品图压缩率高、轻松达标;而包装印满文字与规格标签的复杂图压缩率最低、最易被压花,而这正是最需要看清文字的一批。
4. 放宽字节预算不增加任何 token 成本,是三条候选路径(降分辨率 / 放宽预算 / quality 地板降级)中代价最小的一条。

**已确认**:长边上限锁定 2048px。下游 Qwen3-VL-Flash 调用必须显式设置 `max_pixels >= 2048 * 2048`;否则服务端默认像素/token 上限可能再次下采样,浪费本模块保留的分辨率。

**保留可配置性**:模型或调用策略变化时,内部 downsample 阈值也可能变化。若下游阈值低于 2048,为注定被丢弃的像素牺牲 quality 会构成双重损失,因此长边上限仍为配置项。

### D-IMG-04:pass-through 条件门

**决策**:当且仅当 `长边 ≤ 2048px`、`原文件 ≤ 300KB` 且 `EXIF orientation ∈ {1, 缺失}` 时,原样透传,零重编码。任一条件不满足则进入 resize + 重编码路径。需要方向校正的图片不能透传,否则校正只发生在内存中而不会体现在输出字节里。

**依据**:

1. **避免 generation loss**:源图多数已是有损压缩产物(Tesco / Argos 商品图均为此类)。对已压缩图再解码重编码会叠加一次代际损失,若原图本已达标则纯亏无收益。
2. **为何必须是双条件**:单看文件大小会漏过"高分辨率 + 高压缩率"的情形——白底简洁构图的商品图可能 3000×3000 但仅 120KB,只看字节会误判透传,违背 D-IMG-03 的主约束定位。
3. 按 Tesco / Argos 样本推测,该路径可能覆盖多数流量,附带节省 CPU。

**注意**:透传路径下输出格式即原格式,与 D-IMG-01 的默认 JPEG 不一致。元数据必须如实记录实际输出格式,下游不得假设输出格式恒定。

---

### D-IMG-05:处理顺序固定

**决策**:处理步骤顺序为设计约束,不得调整。

```
1. 下载 bytes
2. decode 验证                    ← L3 错误在此捕获
3. EXIF 方向校正                  ← 必须最先(见 D-IMG-10)
4. pass-through 双条件门          ← 命中则结束(见 D-IMG-04)
5. alpha 合成白底 → RGB           ← 见 D-IMG-11
6. resize 至长边上限              ← 见 D-IMG-12 / D-IMG-13
7. quality 收敛循环               ← 见 D-IMG-15
8. 输出 + 结构化元数据
```

**顺序依据**:

- 步骤 3 必须先于步骤 4 与 6:未校正方向时长宽比判断会取错边,导致门判断与 resize 均出错。
- 步骤 4 必须先于 5/6/7:透传的意义就是跳过全部重编码环节。
- 步骤 5 必须先于 7:JPEG 不支持 alpha,合成必须在编码前完成。

---

### D-IMG-06:格式判定依据内容结构,不依据 URL 或 Content-Type

**决策**:图片真实格式以能否成功 decode 为准。URL 扩展名与 HTTP `Content-Type` header 仅作辅助参考,不作为判定依据。

**依据**:

1. URL 不可信:样本中 Argos 的 `media.4rgos.it/i/Argos/7726851_R_Z001A` 完全无扩展名。此外 CDN 常见 `.xxx.webp` 形式的多段命名,中间段为站点内部变体标识而非格式标识。
2. header 不可信:CDN 配置错误或返回占位页时 header 可能与实际内容不符。
3. 与 scraping 模块 "invalid target detection 依据结构信号而非关键词" 属同一原则的延伸:不信任表面字符串,只信任实际内容结构。

---

### D-IMG-07:错误按层分类,可重试性由层级决定

**决策**:采用四层错误分类,每层绑定固定的重试策略。

| 层级 | 触发条件 | 可重试 | 处理策略 |
|---|---|---|---|
| **L1 网络层** | timeout / connection refused / DNS 失败 | 是 | 常规重试 |
| **L2a HTTP 限流** | 403 / 429 | 是 | 指数退避重试 |
| **L2b HTTP 服务端** | 5xx | 是 | 常规重试 |
| **L2c HTTP 死链** | 404 | 否 | 直接标记失败 |
| **L3 内容层** | status 200 但 decode 失败 | 否 | 标记"返回非有效图片" |
| **L4 语义层** | decode 成功但尺寸异常小 | 否 | 标记可疑,**不判失败** |

**分层依据**:

- **L3 是高频真实坑位**:大量 CDN 对不存在的资源返回 200 + HTML 错误页或占位图。仅检查 status code 会将其误判为成功,并把无效内容送进 matching 环节污染结果。
- **L4 不判失败而标记可疑**:1×1 tracking pixel、通用占位图标等属于"技术上成功但语义上无用"。直接判失败会丢失信息;标记可疑可留给人工 review,后续可演进为占位图指纹库比对。此设计与项目既有原则一致——终态应可查询,不做 destructive 处理。

---

### D-IMG-08:单条失败不中断批次,全量结构化返回

**决策**:每条 URL 的处理结果均为结构化返回值,失败条目携带错误层级与详情,不以异常形式中断整个批次。

**依据**:与项目既有的 `rejected` 状态设计原则一致——失败是可查询的状态而非数据销毁的终点。批量抓取中单张图失败属常态,不应导致整批重跑。

---

### D-IMG-09:HTTP client 抽象为可替换接口,第一版不接入 Bright Data

**决策**:第一版使用常规 async HTTP client 直连。client 抽象为可替换接口。

**依据**:

1. 图片 CDN 域名(如 `digitalcontent.api.tesco.com`)与主站反爬强度通常不同——图片 CDN 需服务浏览器直接加载,一般更宽松。Tesco 主站需 Scraping Browser 是 Akamai TLS 指纹所致,该结论**不可直接外推**至其图片 CDN。
2. 但也不默认直连必然可行,故保留接口可替换性:若实测出现高频 L2a 错误,再评估接入 Bright Data Web Unlocker。
3. 符合项目 phase-gated 原则:不预先重复建设 anti-bot 能力,由实测数据驱动引入时机。

**触发升级的信号**:某 retailer 图片 CDN 的 L2a 错误率持续超过阈值。

---

### D-IMG-10:强制 EXIF 方向校正

**决策**:decode 后立即应用 EXIF orientation 校正。

**与透传的交互**:orientation 不是 1 或缺失时必须跳过 D-IMG-04 透传门并重编码,确保校正落入输出字节。

**依据**:部分图片(尤其 marketplace 卖家自行上传的,如样本中 Tesco `/marketplace/` 路径下的图)带 EXIF orientation 标记。解码库默认不自动应用,导致浏览器显示正常但处理后横躺。方向错误会同时污染长宽比判断(D-IMG-04 门判断、D-IMG-12 resize)与送入 vision 模型的图像内容。

---

### D-IMG-11:alpha 通道显式合成白底

**决策**:含 alpha 通道的图片(RGBA / LA / P 模式)必须显式合成到白色背景后再转 RGB,不得直接转换。

**依据**:JPEG 不支持透明通道,直接转 RGB 会将透明区域渲染为**黑色**。商品图普遍为透明底或白底,该缺陷会使白底商品变为黑底,对 vision 模型识别是灾难性的。P(调色板)模式亦须走此路径,因调色板图同样可能携带透明色。

---

### D-IMG-12:重采样算法使用 LANCZOS

**决策**:缩放采用 LANCZOS 重采样。实现上优先使用先做整数倍 reduce 再精细重采样的 thumbnail 式接口。

**依据**:

1. LANCZOS 基于 sinc 函数,在**缩小**场景下对边缘与细节保持最好,直接服务于 D-IMG-02 所述的文字 / logo / 标签保护目标。
2. 本模块瓶颈在网络 IO 而非 CPU,重采样质量优先于计算开销。
3. thumbnail 式接口在大幅降图(如 3000→2048)时通过整数倍预缩显著提速,质量接近,且天然满足保持长宽比与 D-IMG-13 只缩不放两项要求,比手工计算 scale factor 更不易出错。

---

### D-IMG-13:绝不放大

**决策**:长边小于上限的图片保持原尺寸,不执行 upscale。

**依据**:插值放大不产生任何新信息,仅撑大文件体积并增加 token 消耗,无任何收益。上限是天花板而非目标值。

---

### D-IMG-14:异步并发,semaphore 限流

**决策**:asyncio 并发模型,以 semaphore 控制并发上限。每条 URL 独立 timeout。

**初值**:并发上限 = 8。

**依据**:与 `link_search` 模块的 LangGraph 全异步取向一致。8 为保守起步值,目的是避免首轮实测即触发 CDN 限流(L2a)而污染对直连可行性的判断——D-IMG-09 是否需要升级到 Bright Data,取决于一个干净的错误率基线。待实测确认各 CDN 容忍度后可上调。

timeout 与重试次数仍不预设,由实测确定。

---

### D-IMG-15:quality 收敛策略

**决策**:第一版采用固定步长递减收敛。若实测显示循环次数成为瓶颈,再切换为二分查找。

**依据**:

1. 二分查找通常 4 次内收敛且能找到**满足预算的最高 quality**,而固定步长找到的是"第一个碰巧达标的 quality",理论上更优。
2. 但 D-IMG-03 放宽预算至 300KB 后,预期多数图片首次编码即达标,收敛循环并非热点路径。第一版按简单实现优先,避免过早优化。
3. 须设置 **quality 地板**:低于地板时块效应与边缘振铃将损害 D-IMG-02 所保护的目标。触底仍超预算时的处理见 D-IMG-16。

---

### D-IMG-16:quality 触底仍超预算 → 标记无法达标,走人工 review

**决策**:quality 递减至地板后文件仍超 300KB 时,**不继续降 quality,不降分辨率**,标记为 `budget_unmet` 状态并送入人工 review 队列。

**产物保留策略**:该状态下**保留地板 quality 的编码产物**,不丢弃、不返回空。理由是丢弃会使该 SKU 完全失去图片,而超预算产物在功能上仍可用——字节预算是次级约束(D-IMG-03),超标不产生 token 成本,仅多耗带宽与存储。review 环节据此决定放行、人工替换图源,还是单条豁免预算。

**依据**:

1. 不降 quality:地板存在的意义即是保护 D-IMG-02 的文字 / logo / 标签目标,击穿地板等于放弃本模块的核心质量承诺。
2. 不降分辨率:分辨率是主约束(D-IMG-03),为次级约束牺牲主约束属倒置。
3. 走 review 而非静默放行:与项目既有原则一致——异常终态应可查询、可干预,而非静默降级。

**已知代价(须监控)**:压缩率最低的图片正是包装印满文字与规格标签的复杂图,而这恰是 matching 环节最依赖的一类。因此 review 队列存在被高价值图片填满的结构性风险。若 `budget_unmet` 比例超出可人工处理的规模,应视为 D-IMG-03 的 300KB 取值偏紧的信号,优先上调预算而非收紧其他参数。

## 3. 支持格式范围

| 类别 | 决策 |
|---|---|
| JPEG / PNG / WebP / GIF | 支持 |
| SVG(矢量) | **不支持**,归入 L3 错误 |
| HEIC / AVIF | 暂不支持,归入 L3。遇到实际样本再评估是否引入解码插件 |

**依据**:商品图 CDN 出现矢量图的概率极低,不为此引入额外依赖。HEIC/AVIF 采用 phase-gated 策略,由实测样本驱动。

## 4. 输出元数据字段

每条处理结果须包含:

| 字段 | 说明 |
|---|---|
| `url` | 原始输入 URL |
| `status` | success / failed / suspicious(L4) / budget_unmet(D-IMG-16) |
| `original_format` | decode 判定的真实格式(非 URL 推断) |
| `original_dimensions` | 原始像素尺寸 |
| `original_size_bytes` | 原始文件字节数 |
| `output_format` | 实际输出格式(透传路径下可能非 JPEG,见 D-IMG-04) |
| `final_dimensions` | 输出像素尺寸 |
| `final_size_bytes` | 输出文件字节数 |
| `passthrough` | 是否命中 D-IMG-04 透传路径 |
| `final_quality` | 收敛后的 quality 值;透传路径为空 |
| `error_layer` | 失败时填,取值见 D-IMG-07 层级 |
| `error_detail` | 失败时填 |
| `retry_count` | 实际重试次数 |

**依据**:原始尺寸与最终尺寸均需保留,用于事后校准 D-IMG-03 的阈值取值,以及评估透传路径实际覆盖率。裸字节返回不满足此需求。

## 5. 与其他模块的关系

| 模块 | 关系 |
|---|---|
| scraping / parser | 上游。提供图片 URL,不提供图片内容 |
| matching | 下游。仅消费归一化产物与元数据,不感知本模块内部策略 |
| storage | 归一化产物的缓存与持久化。同一 SKU 图片若被多轮 matching 复用,须命中缓存,不得重复下载与重复压缩 |
| run_id 追溯体系(S2) | 每次处理须可归属到 run_id |

## 6. 未决问题

### Q4:L4 尺寸异常的判定阈值 —— 延后,不阻塞第一版

**处置**:第一版不实现尺寸异常判定,L4 层保留在错误分类体系中但不触发。

**依据**:阈值取值需真实样本支撑,预设阈值有误判风险。第一版先积累元数据中的 `original_dimensions` 分布,据此反推合理阈值。占位图指纹库为后续演进方向,非本版范围。

**引入信号**:matching 环节出现由占位图 / tracking pixel 导致的误匹配。

### 待实测确定的参数(非阻塞)

| 参数 | 状态 |
|---|---|
| timeout | 初值 connect 5s / read 20s,继续监控 |
| 重试次数(按 D-IMG-07 分层) | 初值 L1=2 / L2a=3 / L2b=2,继续监控 |
| quality 起始值与地板值 | 初值 90 / 65;地板仍须以校准脚本的文字可读性结果复核 |
| 并发上限是否上调 | 初值 8,见 D-IMG-14 |
| 长边上限是否需下调 | 锁定 2048,选型落定后核对一次,见 D-IMG-03 |
